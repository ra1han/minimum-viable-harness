The core primitives

Sensor, Gate and Backpressure

Sensors

System's eyes and ears, providing deterministic and objective evidence.

Gates

Strict, conditional rule/policy that defines when a check must happen.

Backpressure

The friction - blocking progress until the condition is met.

Building blocks

The harness is an onboarding packet that can execute.

A good new engineer needs docs, scripts, context, and a way to know when the work is correct. So does an agent.

Boot

Setup commands

Dependencies, environment, database, and local services.

Run

Happy path

The shortest route to start the app in a known-good state.

Verify

Proof loop

Tests, type checks, screenshots, logs, or manual smoke paths.

Remember

Session learning

Capture the thing that would save the next agent five minutes.

Self-improving feedback loop

Every session should leave the harness sharper.

After each run, capture what would have made setup, execution, or verification faster and more reliable.

Improve the next run

Observe

Where did the agent stall or guess?

Capture

Turn the lesson into memory, docs, checks, or scripts.

Reuse

The next session starts with the lesson available.

Verify

Confirm the loop really got shorter.

Close

A harness is the difference between a clever model and a dependable teammate.

The minimum bar: the agent can understand the repo, run the app, verify its work, and improve the path for whoever comes next.
